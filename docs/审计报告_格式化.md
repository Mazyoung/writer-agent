world_setting[:2000] → 3 个追踪文档（3000/2000/1500 截断）→ 近 3 章事实摘要[:2500] → 上章结尾[-800:] → 额外指示。
⚠ 其中卷规划事件和 book_plan 在纯 main.py 流程下永远为空（#4）。

参数传入但未使用：build_writer_prompt(world_setting)（P0）；SceneSpec.transition；main.py:157 的 final_prompt
变量；main.py:116 的 INTERACTIVE_QUESTIONS import；orchestrator 的 dataclasses import；state_manager 的

交互模式上下文缺失：plan_from_interactive_answers 不含 world_setting、book_plan、修炼体系、事实摘要、上章结尾 →
交互模式规划质量系统性低于非交互模式。

## 6. StateManager 三职责现状

- 输入：章正文、章号、章规划文本、3 个追踪文档。不接收 world_setting / volume_plan → prompt 要求做
  T1「与设定矛盾」检查，但设定根本没给它。
- 输出：states/review_ch*.md（原始分析）、tracking/*.md（追加式更新）、states/post_chapter_update_ch*.md、states/fact_
  digest_ch*.md、SQLite character_state。
- Consistency Review：只存在于 LLM 输出文本中——不打印、不解析、不拦截，T1 硬错误也不会告知用户，需人工翻文件。
- Quality Review：同上，PASS/MINOR/MAJOR 评级无任何消费者。
- State
  Update：只追加日志（change_log/item_logs/rule_changes），现状表（关系条目、主角持有物品表、角色修炼状态表）从不更新 →
  追踪文档的「当前状态」随章节推进持续失真，而这正是 Part B 的原料。物品解析器期望「获得/消耗/失去」分组，但 prompt
  约定的是「物品名： 旧状态 → 新状态」扁平列表 → 物品变更大概率丢失或错分类。
